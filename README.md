# cc-retain-lab

CC_Codex 二期（26.11）**数据工程**产品线：**留存裁撤台**（FastAPI + 原生 JS SPA + SQLite）。

## 一句话骨架（自有，非外仓抄题）

**分区留存策略版本 → 到期扫描裁决 → 归档或销毁执行 → 策略与实物分区对账**

与现有六线正交（不是采集目录、ETL 管道、同步源、解析入库、编排流、种子摄取）。  
也不碰外仓常见指纹（Feed 归并 / 作业编排 / CDC 游标 / 质检签发 / 贴源-明细-汇总）。

## 领域

- **所属领域**：数据工程  
- **子方向**：数仓与数据湖（分区留存 / 裁撤闭环）

## 技术栈

| 层 | 选型 |
|----|------|
| 后端 | Python 3.12、FastAPI、Uvicorn、SQLite |
| 前端 | 原生 JS 单页（全中文），青灰底 + 铜强调，顶栏导航（非绿侧栏克隆） |
| 测试 | pytest + httpx（本地秒级闭环，优先于 compose） |

## 基线已通主链

1. 现行留存策略（主题域 / 保留天 / 到期动作）  
2. 实物分区列表（在线 / 归档 / 销毁）  
3. 按基准日到期扫描 → 生成待执行裁决  
4. 单条裁决执行（归档写地址 / 销毁清零）  
5. 策略与实物对账报告  

## 跨域依赖守卫（retain-07）

解决「下游仍引用上游时上游被销毁 → 落库链路断档、分区列表却假成功」。

### 依赖处置二选一：整单拒绝（非只读冻结）

在「整单拒绝」与「只读冻结」两条处置路线中，本实现取 **整单拒绝 + 整笔退回**：
只读冻结仅作为被拒单据在页面上的呈现（只读卡片 + 拒绝原因，依赖解除后可重试），
不是独立处置路径；这样与「依赖半截须整笔退回」的单事务原子回滚天然同构。

### 同源与拦截

- 新增 `partition_dependencies`（下游→上游依赖对象，解除留痕）与
  `dependency_snapshots`（每次执行在**同一连接、同一事务、同一序列化点**对
  「依赖集合 + 上下游分区态」拍快照，记 `aligned/block_reason`），保证快照与分区态同源。
- 销毁上游前对齐校验：仍被在线/裁撤中下游引用 → 不对齐；目标分区自身参与的有效依赖
  任一端已销毁（断链）→ **断链即拦**（任何动作都拦）。
- 拦截时不改动任何分区态（分区从未离开「在线」，无半截写入），写 `ok=0` 执行流水与
  拒绝原因后提交留痕，HTTP 层以 409 返回拒绝原因与快照。
- 写流程入口 `BEGIN IMMEDIATE` + `busy_timeout` 拿库级写锁，两人并线串行化，
  杜绝依赖快照互盖与半截依赖。
- 对账报告新增 `broken_dependency_count` 断链列（旧库启动时幂等补列）。

### 三面联改

- **跨域依赖卡片页**：登记/解除依赖对象，展示上下游分区态。
- **分区队列（实物分区）**：增「下游引用 / 上游依赖」计数，被引上游显式标红。
- **策略详情（留存策略）**：每个主题域展开关联的跨域依赖处置面。
- 裁决页对被拒单据渲染只读拒绝卡片（拒绝原因 + 重试入口），页面直接写出依赖对象。

### 新增 API

| 方法 | 路径 | 说明 |
|----|------|------|
| GET | `/api/dependencies` | 依赖对象列表 |
| POST | `/api/dependencies` | 登记跨域依赖（同域/自指/指向已销毁 → 400/409） |
| POST | `/api/dependencies/{id}/deactivate` | 解除依赖（留痕） |
| GET | `/api/dependency-snapshots` | 同源依赖快照（含对齐结论与拒绝原因） |

测试见 `tests/test_dependency_guard.py`（拦截、断链即拦、原子退回、并线写锁、快照同源）。
